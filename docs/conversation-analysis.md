# 矿眸智探：分析式问答

问答页 `/chat` 支持围绕矿产新闻、政策、市场与业务场景解释原因、分析可能影响、提出行动建议，并保留最近五轮对话。一般行业概念可以直接解释；实时行情和具体事件需要资料支持。

## 使用示例

- 「最近铜矿项目进展对供应有哪些可能影响？我负责采购，应该关注什么？」
- 接着问「那我们下一步该怎么做？请给我可执行的建议。」
- 「解释一下资源量与储量的区别，讲清楚为什么会影响项目判断。」
- 「2026年锂矿价格走势如何？能推论接下来可能发生什么影响吗？」

资料覆盖不足时，回答应说明缺口，并提供分析框架和需要核实的信息。少量现货价格点不能代表全年走势，项目经济测算中的假设价格也不能当作实际报价。

资源量与储量的解释补充了经过核对的 JORC 分类依据，参考[澳大利亚地球科学局的术语说明](https://www.ga.gov.au/aimr2023/appendices)。解释时明确所采用的分类体系，避免把全部资源量当作未勘探资源或可供开采的储量。基本概念解释独立于新闻检索，避免给术语定义附上不支持定义的钻探新闻引用。

## 回答与引用

模型输出按含义分段：`fact` 为资料事实，`analysis` 为条件性推断，`advice` 为应对建议，`background` 为一般行业知识，`clarification` 为补充问题。

事实引用采用来源编号与 `span` 片段编号。系统从检索到的原文中提取连续片段，保留原文章字符位置；模型不需要重新抄写外文引文。数字、币种、单位与百万／十亿等数量级分别校验。不存在的片段、无依据数字或收益保证会被拒绝；独立有效的分析段落可以保留。

引用中的原文位置和数量一致性校验保证可追溯性，不等于验证所有语义推断。回答标明分析、建议和一般行业知识，用户可通过来源卡片核对论据和原文。

`ChatOut.mode` 增加 `analytical`（使用资料并提供分析）和 `general`（一般知识或分析框架），兼容原有 `grounded`、`extractive`、`insufficient`、`identity`。一般流程建议不强行附上无关引用。模型不可用时显示简短中文资料线索，明确未生成完整分析，不把原文摘录包装成分析结论。

## 多轮与前端

简短追问继承最近的矿种、地区与年份；天气等无关问题不继承矿产话题。当前问题和回答重点放在长篇资料之后，帮助模型区分本轮是分析、行动方案还是概念解释。

前端通过 SSE 显示处理进度，完整回答校验后才发送文字片段和来源。点击引用编号展开对应来源卡片，外文原文默认折叠。历史记录保留，旧对话不会自动重新生成分析回答。

## 运维

沿用服务端已有 LLM 配置与并发限制，不加载新的本地模型，不新增常驻容器。`consultation_blocks_rejected` 日志记录拒绝原因和数量，不记录客户问题、完整模型回答或密钥。

回归覆盖原文片段定位、重复句的位置、伪造引用与数量、数量级及单位变更、一般建议、概念解释、话题继承、中文呈现和模型不可用时的处理。公网验证另外检查真实模型回答、保存的追问、原文章片段、来源点击和手机端布局。
